How I Cut Report Generation Time by 85% with Laravel Queues & Redis

Shah Md. Arafatul Rahman · 5 min read

The Problem

A client's e-commerce platform was generating daily analytics reports that summarized millions of order events. Each report request would lock the request thread for up to 40 seconds, causing timeouts and a terrible user experience. The dashboard was essentially unusable during peak hours.

Root Cause Analysis

The original code ran everything synchronously in a single controller method: fetching records, aggregating data, generating CSV files, and sending emails — all in one blocking request. With 2M+ rows in the orders table and no indexing strategy, even a simple GROUP BY query took 15+ seconds.

  • No database indexes on frequently-queried columns
  • Synchronous file generation blocking the HTTP thread
  • No caching — same expensive queries ran on every request
  • Email sending was inline, adding another 2–5 seconds

The Solution: Laravel Queues + Redis

I refactored the entire report pipeline into a queued job system. When a user requests a report, the controller dispatches a job and immediately returns a "processing" response. Redis acts as the queue driver, and a separate worker processes the job asynchronously.

// ReportController.php public function generate(Request $request) { $job = new GenerateAnalyticsReport( auth()->user(), $request->date_range ); dispatch($job)->onQueue('reports'); return response()->json([ 'status' => 'queued', 'message' => 'Your report is being generated.', ]); }

Adding Redis Caching

For frequently requested date ranges (last 7 days, last 30 days), I added a Redis cache layer with a 1-hour TTL. This means repeated requests for the same report serve instantly from cache instead of re-querying the database.

// Inside GenerateAnalyticsReport job $cacheKey = "report:{$this->user->id}:{$this->dateRange}"; $data = Cache::remember($cacheKey, 3600, function () { return Order::whereBetween('created_at', $this->range) ->selectRaw('DATE(created_at) as date, SUM(total) as revenue, COUNT(*) as orders') ->groupBy('date') ->get(); });

Results

  • Report generation time: 40s → 6s (85% reduction)
  • HTTP response time: 40s → <100ms (instant queue dispatch)
  • Server load: Reduced by ~60% during peak hours
  • User experience: Dashboard now shows real-time progress via polling

Key Takeaways

Moving long-running operations off the HTTP thread is one of the highest-impact optimizations you can make in Laravel. The combination of Redis queues + caching is a proven pattern for any report generation, data export, or notification system. Start with this before reaching for more complex solutions.
